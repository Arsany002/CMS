\chapter{API Endpoints Breakdown}
\label{chap:endpoints}

\chapterintro{%
  This chapter is the authoritative reference catalogue for every HTTP
  endpoint exposed by the Clinic Management API. Endpoints are organised
  by role surface: public authentication routes, Super Administrator
  routes, Doctor routes, and Assistant routes. For every endpoint the
  catalogue provides the HTTP method and URI, the required request
  headers, a concrete JSON request payload where applicable, and a
  concrete JSON success response. All UUID values shown are illustrative
  examples only.
}

\begin{notebox}[Common Request Headers]
  Unless stated otherwise, every authenticated endpoint requires the
  following two headers:
  \begin{itemize}
    \item \texttt{Authorization: Bearer \{access\_token\}} --- the
      Personal Access Token obtained from the login endpoint.
    \item \texttt{Accept: application/json} --- instructs Laravel to
      return JSON error responses rather than HTML for validation
      failures and exceptions.
    \item \texttt{Content-Type: application/json} --- required on all
      \texttt{POST}, \texttt{PUT}, and \texttt{PATCH} requests that
      carry a JSON body.
  \end{itemize}
\end{notebox}

\section{Authentication Endpoints}
\label{sec:ep-auth}
%% =========================================================================

The authentication endpoints are grouped under the
\route{/api/v1/auth/} prefix. The login endpoint is public; logout and
profile retrieval require a valid bearer token.

%% ── EP-AUTH-1 ─────────────────────────────────────────────────────────────
\subsection{Login}
\label{ep:auth-login}

\begin{table}[h!]
  \renewcommand{\arraystretch}{1.3}
  \begin{tabularx}{\linewidth}{@{}L{3cm} X@{}}
    \toprule
    \rowcolor{PrimaryBlue}

    \midrule
    Authentication & None (public endpoint) \\
    \rowalt
    Role Required  & --- \\
    Success Status & \stok{} \\
    \bottomrule

Validates the supplied email and password against the database, checks
that the account is active, and issues a Passport Personal Access Token.

\begin{lstlisting}[style=bash]

\end{lstlisting}

\textbf{Request Body}

\section{Super Administrator Endpoints}
\label{sec:ep-admin}
%% =========================================================================

All Super Administrator endpoints are grouped under the
\route{/api/v1/admin/} prefix and require the \texttt{role:super\_admin}
middleware. A Doctor or Assistant token will receive \stforbid{} on
every route in this section.

%% ── EP-ADMIN-1 ────────────────────────────────────────────────────────────
\subsection{Dashboard --- System KPI Aggregate}
\label{ep:admin-dashboard}

\begin{table}[h!]
  \renewcommand{\arraystretch}{1.3}
  \begin{tabularx}{\linewidth}{@{}L{3cm} X@{}}
    \toprule
    \rowcolor{PrimaryBlue}
    \multicolumn{2}{@{}l}{\tblhdr{GET \quad /api/v1/admin/dashboard}} \\
    \midrule
    Authentication & Bearer token required \\
    \rowalt
    Role Required  & \texttt{super\_admin} \\
    Query Params   & \texttt{from\_date} (optional, \texttt{YYYY-MM-DD}),
                     \texttt{to\_date} (optional, \texttt{YYYY-MM-DD}) \\
    \rowalt
    Success Status & \stok{} \\
    \bottomrule
  \end{tabularx}
\end{table}

Returns system-wide aggregate KPIs: total counts for clinics, users,
patients, and appointments. When \texttt{from\_date} and
\texttt{to\_date} are supplied, the appointment breakdown is filtered
to that date range.

\textbf{Request Headers}

\begin{lstlisting}[style=bash]
Authorization: Bearer {access_token}
Accept: application/json
\end{lstlisting}

\textbf{Example Request}

\begin{lstlisting}[style=bash]
GET /api/v1/admin/dashboard?from_date=2025-01-01&to_date=2025-12-31
\end{lstlisting}

\textbf{Success Response --- HTTP 200 OK}

\begin{lstlisting}[style=json]

\section{Assistant Endpoints}

All Assistant endpoints are grouped under the
\route{/api/v1/assistant/} prefix and require both the
\texttt{role:assistant} middleware and the \texttt{clinic.scope}

\subsection{Query Available Appointment Slots}
\label{ep:assistant-available-slots}

\begin{table}[h!]
  \renewcommand{\arraystretch}{1.3}
  \begin{tabularx}{\linewidth}{@{}L{3cm} X@{}}
    \toprule
    \rowcolor{PrimaryBlue}
    \multicolumn{2}{@{}l}{\tblhdr{GET \quad /api/v1/assistant/available-slots}} \\
    \midrule
    Authentication & Bearer token required \\
    \rowalt
    Role Required  & \texttt{assistant} \\
    Clinic Scope   & Enforced \\
    \rowalt
    Query Params   & \texttt{doctor\_id} (required, UUID),
                     \texttt{date} (required, \texttt{YYYY-MM-DD}) \\
    \rowalt
    Success Status & \stok{} \\
    \bottomrule
  \end{tabularx}
\end{table}

Computes and returns the list of available appointment start times for a
specific doctor on a specific date. The algorithm loads the doctor's
\phpclass{DoctorSchedule} for the corresponding day of the week,
generates all candidate slots at \texttt{slot\_duration}-minute
intervals, and subtracts any slots already occupied by
non-cancelled appointments.

\textbf{Example Request}

\begin{lstlisting}[style=bash]
GET /api/v1/assistant/available-slots
    ?doctor_id=9d2b1f4e-3a7c-4e8d-b1f2-3a7c4e8db1f2
    &date=2026-07-07
\end{lstlisting}

\textbf{Success Response --- HTTP 200 OK}

\begin{lstlisting}[style=json]
{
  "success": true,
  "message": "Available slots retrieved successfully.",
  "data": {
    "doctor_id":     "9d2b1f4e-3a7c-4e8d-b1f2-3a7c4e8db1f2",
    "date":          "2026-07-07",
    "slot_duration": 30,
    "available_slots": [
      "09:00",
      "09:30",
      "10:30",
      "11:00",
      "11:30",
      "12:00",
      "12:30",
      "13:00",
      "13:30"
    ]
  }
}
\end{lstlisting}

\begin{notebox}[Empty Slots Array]
  If the doctor has no schedule entry for the given date's day of the
  week, or if all slots are already booked, the
  \texttt{available\_slots} array is empty. This is a valid \stok{}
  response, not an error.
\end{notebox}

%% ── EP-ASS-8 ──────────────────────────────────────────────────────────────
\subsection{Book Appointment}
\label{ep:assistant-appointments-store}

\begin{table}[h!]
  \renewcommand{\arraystretch}{1.3}
  \begin{tabularx}{\linewidth}{@{}L{3cm} X@{}}
    \toprule
    \rowcolor{PrimaryBlue}
    \multicolumn{2}{@{}l}{\tblhdr{POST \quad /api/v1/assistant/appointments}} \\
    \midrule
    Authentication & Bearer token required \\
    \rowalt
    Role Required  & \texttt{assistant} \\
    Clinic Scope   & Enforced \\
    \rowalt
    Restrictions   & The requested slot must be available (within the
                     doctor's schedule and not already booked). A
                     distributed cache lock prevents concurrent
                     double-booking. \\
    \rowalt
    Success Status & \stcreated{} \\
    \bottomrule
  \end{tabularx}
\end{table}

Books an appointment by linking a patient to a doctor's available slot.
The system:
\begin{enumerate}
  \item Acquires a distributed \texttt{Cache::lock} keyed to
    \texttt{appointment\_slot:\{doctor\_id\}:\{date\}:\{start\_time\}}.
  \item Validates that the requested \texttt{start\_time} appears in
    the computed available slots for that doctor and date.
  \item Computes \texttt{end\_time} as
    \texttt{start\_time + slot\_duration}.
  \item Persists the appointment record with status \texttt{pending}.
  \item Dispatches the \texttt{SendAppointmentConfirmation} job
    asynchronously.
  \item Releases the lock.
\end{enumerate}

\textbf{Request Body}

\begin{lstlisting}[style=json]
{
  "doctor_id":        "9d2b1f4e-3a7c-4e8d-b1f2-3a7c4e8db1f2",
  "patient_id":       "6d7e8f9a-0b1c-2d3e-4f5a-6b7c8d9e0f1a",
  "appointment_date": "2026-07-07",
  "start_time":       "10:00",
  "notes":            "First visit. Patient complains of knee pain."
}
\end{lstlisting}

\textbf{Validation Rules}

\begin{table}[h!]
  \renewcommand{\arraystretch}{1.3}
  \begin{tabularx}{\linewidth}{@{}L{4cm} L{3.5cm} X@{}}
    \toprule
    \rowcolor{PrimaryBlue}
    \tblhdr{Field} & \tblhdr{Rules} & \tblhdr{Notes} \\
    \midrule
    \texttt{doctor\_id}        & required, uuid, exists:users,id
                                 & Must be a Doctor-role user in the same clinic. \\
    \rowalt
    \texttt{patient\_id}       & required, uuid, exists:patients,id
                                 & Must belong to the same clinic. \\
    \texttt{appointment\_date} & required, date, after\_or\_equal:today
                                 & Cannot book in the past. \\
    \rowalt
    \texttt{start\_time}       & required, date\_format:H:i
                                 & Must match an available slot. \\
    \texttt{notes}             & nullable, string            & Optional booking notes. \\

\end{table}

\section{Common Error Response Reference}
\label{sec:common-errors}
%% =========================================================================

The following error shapes are returned consistently across all endpoints.

\begin{table}[h!]
  \centering
  \caption{Common HTTP error responses and their trigger conditions.}
  \label{tab:common-errors}
  \renewcommand{\arraystretch}{1.5}
  \begin{tabularx}{\linewidth}{@{}C{2.5cm} X@{}}
    \toprule
    \rowcolor{PrimaryBlue}
    \tblhdr{Status} & \tblhdr{Trigger and Shape} \\
    \midrule
    \stunauth{}
      & Missing, malformed, or revoked bearer token. The
        \texttt{auth:api} Passport middleware terminates the request.
        \newline
        \texttt{\{"success": false, "message": "Unauthenticated."\}} \\
    \rowalt
    \stforbid{}
      & Role mismatch (\phpclass{RoleMiddleware}); cross-clinic access
        (\phpclass{ClinicScopeViolationException}); self-demotion
        attempt (\phpclass{SelfDemotionException}); deactivated account
        (\phpclass{AccountDeactivatedException}).
        \newline
        \texttt{\{"success": false, "message": "<context-specific message>"\}} \\
    \stnotfound{}
      & Route model binding failed to resolve the UUID path parameter
        to an existing record (\texttt{ModelNotFoundException}).
        \newline
        \texttt{\{"success": false, "message": "Resource not found."\}} \\
    \rowalt
    \stconflict{}
      & A booking or reschedule request targets a slot that is already
        occupied (\phpclass{AppointmentConflictException}).
        \newline
        \texttt{\{"success": false, "message": "The requested appointment slot is not available."\}} \\
    \stunproc{}
      & Form request validation failure (structured field errors under
        \texttt{"errors"} key); or an operation on a resource in an
        incompatible state
        (\phpclass{InvalidAppointmentStateException}).
        \newline
        \texttt{\{"success": false, "errors": \{"field": ["message"]\}\}} \\
    \bottomrule
  \end{tabularx}
\end{table}

\begin{lstlisting}[style=json, caption={HTTP 422 validation failure envelope.}]
{
  "success": false,
  "errors": {
    "email":    ["The email field is required."],
    "password": ["The password must be at least 8 characters."]
  }
}
\end{lstlisting}

\begin{lstlisting}[style=json, caption={HTTP 404 resource not found envelope.}]
{
  "success": false,
  "message": "Resource not found."
}
\end{lstlisting}
